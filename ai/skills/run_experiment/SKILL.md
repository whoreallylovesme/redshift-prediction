# run_experiment — запуск эксперимента

## Два правила, без исключений

1. **Всё запускается через Prefect.** Опыт — это flow-YAML в `configs/flows/` (или новая стадия
   во флоу), запуск — `uv run python runtime/pipeline.py --config configs/flows/<flow>.yaml`.
   Отдельные скрипты руками не запускаются; прямые вызовы `runtime/train.py`/`runtime/inference.py`
   — только для отладки одной стадии, их результаты в отчёты не идут. Требование научного
   руководителя: флоу Prefect делает процесс понятным и воспроизводимым.
2. **Вычисления — только на GPU-сервере.** Обучение, прогноз, оценка, Phosphoros, сборка данных,
   вырезки, большие расчёты на pandas/numpy на Mac не запускаются. На Mac — Claude Code и агенты
   (без ограничений), правка кода и текстов, git, просмотр, копирование результатов, сборка PDF.

## Порядок

1. **Постановка.** Записать вопрос, данные и их роли (F/S — обучение и выбор, N — только тест),
   модель, сиды, метрики, критерий успеха (`docs/experiment_setup.md`). Прошлые результаты не
   перезаписываются: новый тег и новый каталог `runs/<эксперимент>_<YYYY_MM_DD>/`.
2. **Флоу.** Новый flow-YAML на основе ближайшего существующего; конфиги моделей — в
   `configs/nn/` или `configs/tabular/`. Код — в `lib/` по реестрам (`runtime/train.py`,
   `lib/inference/engine.py`), без абсолютных путей; ruff и mypy проходят.
3. **Сервер.** Код на сервер — через git (ветка), не копированием файлов руками.
   - `ssh gpu`, `nvidia-smi`, выбрать свободную карту (GPU 0 обычно занята);
   - запуск в `tmux` с понятным именем:
     `CUDA_VISIBLE_DEVICES=N nice -n 5 uv run python runtime/pipeline.py --config configs/flows/<flow>.yaml`;
   - шаги, которые ждут предыдущих, взводятся на сервере (ждут файл-маркер), а не руками;
   - правила общего сервера — `docs/gpu_server_manifest.md`.
4. **Проверка.** Код завершения 0, ожидаемые выходы на месте, метрики пересчитаны независимо
   (на сервере). Для изменений в существующих моделях — сверка с прошлым прогоном на тех же
   данных; побитовые сверки — на CPU сервера (GPU даёт расхождения в 4-м знаке).
5. **На Mac.** Скопировать в `runs/<эксперимент>/` всё нужное для отчётов и воспроизведения:
   HTML-отчёт флоу, метрики, предсказания, конфиги, веса итоговых моделей (сервер могут забрать).
   Большие данные (мозаики, штампы) остаются на сервере.
6. **Отчёт.** Числа — только из артефактов (`facts.json`, `metrics/*.json`); отчёт — скиллом
   `make_report`.

Phosphoros раньше считался на Mac (сборка osx-arm64, `docs/euclid_q1/README.md`); новые прогоны —
на сервере, через conda-окружение `phosphoroscore=2.2.1` для linux-64.

## Чего не делать

- Не запускать обучение, прогноз или Phosphoros на Mac, даже «быстро проверить».
- Не запускать опыт мимо Prefect и не подправлять результаты руками.
- Не использовать метки поля N для обучения, выбора модели или подгонки.
- Не занимать все GPU сервера и не трогать чужие процессы (`pkill -f`, `killall` — нельзя).
