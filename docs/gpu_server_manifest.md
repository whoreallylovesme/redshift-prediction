# Работа на общем GPU-сервере

Сервер общий: им пользуются студенты и кафедра. Цель правил — воспроизводимые прогоны, которые
не мешают другим.

## Ресурсы

- 4× RTX A6000 48 ГБ, 64 ядра, 503 ГБ RAM, большой `/home`.
- Не занимать все GPU и все ядра. Обычный прогон — одна свободная карта и ограниченное число
  потоков (`OMP_NUM_THREADS`, `nice -n 5`). GPU 0 обычно занята кафедральными задачами.
- Свободная память в `nvidia-smi` ещё не значит, что карта свободна: смотреть процессы
  и утилизацию.
- Не дублировать уже идущий процесс (загрузку, обучение, прогноз).

## Подключение и окружение

- `ssh gpu` (адрес, порт и ключ — в локальном `~/.ssh/config`, в репозиторий не попадают).
- Репозиторий, данные и эксперименты — только в домашнем каталоге: `<server-root>/repo`,
  `<server-root>/datasets`, `<server-root>/experiments/<эксперимент>`.
- Python 3.13 через `uv` (`<server-root>/repo/.venv`); системный Python 3.8 не подходит. Torch ставится
  с `--index-url https://download.pytorch.org/whl/cu128`: драйвер 12.8, колёса cu13 не работают.
- Общую среду и чужие пакеты не менять; Docker-демон недоступен без администратора.

## Запуск

- Всё запускается через флоу Prefect (`runtime/pipeline.py --config <flow>.yaml`), а не
  отдельными скриптами.
- Каждый эксперимент — в новом каталоге; старые результаты не перезаписываются.
- Долгий процесс — в отдельной сессии `tmux` с понятным именем; команда, конфиг, хеши входов
  и пути выходов сохраняются рядом с результатами.
- `CUDA_VISIBLE_DEVICES=N` задаётся явно.
- Шаги, которые ждут завершения предыдущего, взводятся на сервере (скрипт ждёт файл-маркер),
  а не запускаются вручную.

## Наблюдение и завершение

- Смотреть только свои логи и маркеры прогресса.
- Прогон считается завершённым, когда есть код завершения 0, ожидаемые выходы с хешами и
  пересчитанные метрики. Отсутствие процесса само по себе ничего не доказывает.
- Не трогать чужие процессы. Не использовать `pkill -f` и `killall`: шаблон может совпасть с чужим
  процессом или с собственной оболочкой. Останавливать только по точному PID.

## Ошибки

- Логи и частичные выходы сохраняются.
- Сначала найти причину, потом исправлять; не повторять вслепую и не поднимать лимиты.

## Данные и копии

- Большие данные (мозаики, штампы, веса) живут на сервере.
- Всё нужное для отчётов и воспроизведения — предсказания, метрики, конфиги, веса итоговых моделей —
  копируется и на Mac в `runs/` (сервер могут забрать).
- Копирование: `scp`/`rsync` через `ssh gpu`, около 8 МБ/с с Mac.
- Токены, ключи и пароли не попадают в команды, логи и документы.
