Проверены вложенные ключи, 64-битные идентификаторы и запуск рабочего процесса после чтения в родителе. Для Hayat отдельно сверены пиксели и порядок меток при перестановке строк каталога.

Основной офлайн-пример обучил Ridge и CatBoost на 353 реальных наблюдениях и сравнил их на остальных 89. Современный маршрут проверен также на 128 строках настоящего обучающего DSAT и 48 строках его отдельного теста. Исторический маршрут отработал на тех же 128 строках со своим разбиением. Эти короткие прогоны проверяют контракты данных и артефактов. Публичный шаблон TEDDY требует подготовленных каталогов и изображений, его мультимодальный путь проверен на малых тестовых данных.

## Повторное ревью PR #26

Проверен полный diff опубликованной версии PR `1f752b8` относительно `90208ed` (215 файлов), затем проверены исправления в этой же ветке.

- В CapsNet стадии A и B могли отнести один объект в разные части разбиения. Обе стадии теперь используют разбиение B. Проверены отдельный запуск B, перенос состояния Adam и скорости обучения. Исправлена загрузка старых весов Hayat с пятью каналами.
- Общий CapsNet, энкодеры таблиц и изображений, графовые блоки и модели плотности перенесены в `lib/models/`. Адаптеры `photoz/` определяют научные входы, цели и протоколы. Для CapsNet проверены 57 ключей старого состояния и регрессия температуры по одноканальному изображению.
- Проверены сквозные CPU-запуски исторических Teddy, Hayat и табличного flow. Старые Python-рецепты LLR и GAM снова находят свои модули. Для пяти табличных оценщиков сопоставлены прогнозы по ID, для CLIP — загрузка прежних весов и результаты инференса.
- Изменение размера изображения использует `torchvision.transforms.v2`. Простая обрезка и повороты NumPy сохраняют тип пикселей, включая `uint16`. Проверены одноканальные и многоканальные снимки, центрирование при нечётных полях и равенство пикселей после аугментаций при фиксированном seed.
- Парные доверительные интервалы в отчётах и выборки Euclid используют `scipy.stats.bootstrap` через `lib.metrics.bootstrap`. На фиксированных данных с теми же сидами сверены исторические интервалы, отдельные выборки ансамблей и кратность каждого тайла при калибровке нуль-пунктов. Общая функция работает при отключённом пакете `photoz`.
- Проверены пустые выборки, неполные пересечения ID, пропуски прогноза, история обучения и включение F_VALID в отчёт Euclid. Нативный адаптер Phosphoros сохраняет 64-битные ID и использует ось распределения из FITS для интервалов.
- CLI запуска и `--check` используют общую композицию Hydra/OmegaConf и схемы Pydantic. Проверены все семь архивных flow из базовой ветки и восемнадцать из первой версии PR. В Git остались примеры, конкретные рецепты сохраняются с запуском. Инструкция по восстановлению приведена в [документации пайплайна](pipeline.md#воспроизведение-запуска).

## Проверка реализации

- Выполнены реальные локальные Prefect-flow для обычной табличной и совместной регрессии и для двух нейросетей по фотометрии, с искусственными входами. Конкурентный тест заставляет два независимых метода встретиться на барьере. Состояния задач берутся из API Prefect.
- SQLite MLflow проверен настоящим клиентом. Сопоставлены значения метрик с артефактом, статусы и значения по эпохам. Для повторного рендера проверен сценарий с удалённым исходным файлом прогнозов.
- Для графа прототипов и восстановления маскированной фотометрии проверены обучение на CPU, сохранение выбранного состояния и прогноз при повторной загрузке. Для графа валидационные объекты исключены из банка прототипов.
- На CPU сопоставлены старые и новые вычисления ANNz, CLIP и классификатора морфологии, а для ResMLP и Transformer — выбранные веса и validation MSE после двух эпох. Проверены сохранение и повторная загрузка состояния. Для CatBoost сравнили решение взвешенного GridSearchCV с независимым расчётом по фолдам.
- Нативный Phosphoros Core прошёл отдельный тест на двух искусственных объектах с 64-битными ID и компактной сеткой из 11 узлов. При отсутствии обязательных ресурсов адаптер сообщает причину. Для обычной конфигурации Euclid Q1 предусмотрена научная сетка из 601 узла.
- Автономный HTML проверен в Chrome на ширинах 1440 и 390 px. Проверены выбор модели, сплита и сравнения, кривые обучения и просмотр PDF объекта; при проверке не было внешних запросов или ошибок JavaScript.

## Границы проверки

Полный научный прогон Euclid, производительность на GPU и метрики на закрытых выборках на этой ветке остаются непроверенными. Для воспроизведения нужны исходные данные, опубликованные версии ресурсов и соблюдение [протокола](experiment_setup.md). Поставляемые быстрые тесты используют небольшие искусственные данные. Dockerfile проверен статически, Python-пакет собран в wheel.

Исторический Euclid-flow продолжает возобновление по файлам, указанным в его рецепте. При смене параметров следует указывать новый каталог. Для совместимости оставлены старые пути импортов и загрузка пользовательских доверенных YAML с выражением Python. Рецепты из Git используют именованные фабрики. Старые Teddy-веса без сохранённых статистик требуют исходного каталога нормировки. Сравнения по сырым научным данным и восстановление опубликованных чисел описаны в [документации Euclid](euclid_q1/README.md).
