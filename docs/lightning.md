# Обучение на Lightning

Слои и архитектуры из `lib/models/nn/` реализуют `torch.nn.Module`. Один энкодер можно использовать для предобучения и регрессии. `LightningModule` задаёт функцию потерь, метрики валидации и оптимизатор, а `Trainer.fit` выполняет обучение. Классические табличные оценщики и их фабрики находятся в `lib/models/tabular/` и обучаются через sklearn API.

## Регрессия по снимку и таблице

В примере TEDDY CatBoost читает признаки из общей таблицы, а CapsNet получает по ID соответствующий шестиканальный снимок. Для запуска подготовьте каталоги A и B и изображения по путям, указанным в [едином YAML эксперимента](../examples/configs/teddy.yaml).

```bash
uv run python -m runtime.pipeline --config examples/configs/teddy.yaml
```

Для совместной модели снимка и табличных признаков измените метод на `model: fusion_cnn`, задайте `use_features: true`, а в `params` укажите `image_channels` и число `features`. Обе модальности используют один ID и одну целевую колонку из секции `dataset`.

Статистики изображения и колонок рассчитываются на обучающей части, записываются с именами колонок и применяются к валидации и прогнозу. Изменение состава или порядка колонок при загрузке весов считается ошибкой. Флоу записывает прогнозы по ID, затем строит общий отчёт. Для своего набора данных замените пути, имена колонок и размеры входа.

## Обучение и веса

Общий модуль изображений обучается по MSE и выбирает эпоху с минимальным RMSE на валидации. Параметры лучшей и последней модели записываются в `methods/<имя>/best_model.pt` и `last_model.pt`. Нормировка входов и история обучения сохраняются рядом с весами. Объект `RegressionTask` задаёт функцию потерь, метрики эпохи и правило выбора чекпойнта. Если `head_prefix` не задан, обучаемые параметры модели образуют группу головы; при `freeze_epochs > 0` остальные параметры размораживаются после указанного числа эпох. Явный префикс позволяет выбрать другую группу головы.

Двухстадийный CapsNet не выбирает каталог в коде обучения. Блок `data._target_` в YAML задаёт фабрику, возвращающую `StagedLoaders`. Hayat предоставляет `photoz.data.hayat.staged_capsnet_loaders`, Teddy — `photoz.data.teddy_capsnet.staged_capsnet_loaders`. Форматы файлов, имена колонок и чтение изображений остаются в этих адаптерах; сид, размер обрезки, число каналов и параметры аугментации передаются из общего рецепта. Inference использует собственный `inference.data._target_`, возвращающий `(DataFrame, DataLoader)`. Если включена генерация меток, её реализация задаётся через `labels.generator`; сценарий Hayat находится в `photoz.training.hayat:run_generate`, а универсальный классификатор не зависит от каталога.

В `photoz/models/nn/` находятся нейросети с заданными физическими полосами, бинами и модальностями Euclid. Их предметные модули обучения находятся в `photoz/training/`. В CLIP используется контрастивное предобучение, затем взвешенное дообучение по бинам. Для предобучения отбрасывается неполный батч, а при дообучении он учитывается.

## ResMLP и Transformer на фотометрии Euclid

Табличные ResMLP и Transformer используют один архив проекции NPZ с 14 полосами и фиксированной выборкой F_VALID. В архив входят следующие массивы.
| Массив | Содержимое |
| --- | --- |
| `object_id`, `field_code`, `role_bitmask` | Уникальные `int64` ID, код поля F (1) и исходные биты принадлежности к обучению и валидации |
| `fit_indices`, `valid_indices` | Непустые массивы индексов `int64`. Вместе они покрывают каждую строку ровно один раз |
| `z` | Конечное неотрицательное эталонное красное смещение |
| `raw_flux_ujy`, `raw_error_ujy`, `table_mask` | Три массива формы `[N, 14]` с потоком в микроянских, его погрешностью и булевой маской наблюдений. Требуются как минимум две измеренные полосы |
| `bands`, `table_descriptor` | Имена полос в [исходном порядке](../photoz/data/euclid_transforms.py) и 18 физических характеристик каждой полосы |

Преобразования `arcsinh(flux)` и `log1p(error)` используют среднее и стандартное отклонение по наблюдаемым значениям из `fit_indices`. Обе архитектуры обучаются с AdamW на `log1p(z)`, выбирают первую эпоху с наименьшей MSE на F_VALID и сохраняют её в `selected_state.pt`. Последняя эпоха записывается в `last_state.pt`. Ход обучения и параметры стандартизации доступны в `train_report.json`. Таблица `predictions.parquet` сохраняет исходные ID и порядок `valid_indices`. Метрики этой выборки характеризуют выбор модели на валидации.

[Тест на восьми искусственных объектах](../tests/test_table_neural.py) создаёт минимальную проекцию, обучает обе модели на CPU и сверяет таблицы предсказаний с повторной загрузкой выбранных весов.

```bash
uv run python -m unittest discover -s tests -p test_table_neural.py
```

## Предобучение с маскированием фотометрических полос

Энкодер решает задачу восстановления измеренного потока в скрытой полосе. Нужны уникальные `object_id` типа int64, имена полос `bands`, непересекающиеся `fit_indices` и `valid_indices` типа int64, вместе покрывающие все строки. Массивы `raw_flux_ujy`, `raw_error_ujy` и булева `table_mask` имеют форму `[N, B]`. Допускается отрицательный поток. Для наблюдаемых полос погрешность строго положительна. Данные о красном смещении для обучения не требуются.

Для каждой полосы масштаб равен большему из двух значений на обучающих наблюдениях — 90-го процентиля абсолютного потока и медианы погрешности. Маска оставляет видимой минимум одну измеренную полосу. Объекты менее чем с двумя измеренными полосами пропускаются при вычислении целевой функции. Их число по выборкам записывается в `train_report.json`. В обучении маски меняются, для валидации одна маска фиксируется независимым генератором. Transformer получает видимые потоки, погрешности и признаки доступности, затем предсказывает условное среднее и внутреннюю дисперсию. В Gaussian NLL к ней добавляется дисперсия измерения.

Одна строка `predictions.parquet` соответствует скрытой измеренной полосе. `object_id` и `band` позволяют найти исходное измерение, `measurement_id` служит ключом отчёта. `y_true`, `y_pred` и `observed_sigma` выражены в микроянских. В графиках и таблицах этого флоу используются метрики обычной регрессии.

## Граф прототипов

Две остаточные графовые ступени и вероятностная голова обучаются по замороженным эмбеддингам. Входной NPZ использует те же идентификаторы и индексы выборок, что при маскировании, и следующие массивы.

| Массив | Содержимое |
| --- | --- |
| `embedding`, `z` | Готовые 64-мерные эмбеддинги float32 и эталонное красное смещение каждого объекта |
| `bank_rows` | От 17 до 4096 различных индексов обучающих объектов, int64 |
| `bank_neighbors`, `bank_weights` | По 16 различных соседей на прототип, без петли в себя. Индексы адресуют локальные строки банка. Веса неотрицательны и имеют положительную сумму |
| `query_neighbors`, `query_weights` | По четыре различных банковских индекса и четыре веса для каждого объекта. Все массивы индексов соседей имеют тип int64, веса — float32 |
| `z_edges` | 401 строго возрастающая физическая граница для 400 бинов. Оба края входят в допустимый диапазон целевой величины |
| `context_permutation` | Перестановка строк банка типа int64, обязательна для режима `shuffled` |

Геометрию рёбер и эмбеддинги готовит поставщик входов. Выбор прототипов и построение представления должны опираться на обучающую выборку. Адаптер проверяет принадлежность строк банка к обучению. Для каждой строки модель суммирует сообщения соседей с нормализованными весами. Голова возвращает распределение с постоянной плотностью внутри каждого физического бина. Точечный прогноз — медиана распределения, колонки `q16` и `q84` содержат границы центрального интервала.

Обе модели используют AdamW, сохраняют последнюю эпоху в `last_state.pt` и первую с минимальной валидационной NLL в `selected_state.pt`. Для загрузки энкодера вместе с весами сохраните `train_report.json` с масштабами и порядком полос. Для графа сохраните также исходную схему проекции и геометрию банка.

```bash
uv run python -m unittest discover -s tests -p test_graph_and_masked.py
```

[Тесты входных схем](../tests/test_graph_and_masked.py) строят оба NPZ из искусственных данных, сверяют значения после восстановления выбранных весов, проверяют закрытие скрытых потоков и погрешностей от энкодера и отклонение валидационного объекта в банке прототипов.
