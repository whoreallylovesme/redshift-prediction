# Перенос GZ-морфологии на Euclid Q1: бинарная классификация «эллиптик / спираль»

Дата: 2026-10-11 (правка по 19 замечаниям независимого читателя от той же даты).

Источники сведений: (а) протокол этапа, переданный постановщиком, включая три уточнения от
2026-10-11 — происхождение стампов, конфигурация обучения `gz_morph_v1`, статус повторного
обучения; (б) файлы, проверенные в этой сессии на маке: `docs/euclid_q1/morph_transfer/metrics.json`
(чтение), `docs/euclid_q1/morph_transfer/example_grid.png` (валидность — `file`/`sips`; содержимое —
визуальный анализ изображения), `python_sh/gz_pipeline.sh` (чтение), а также `ls`/`find`-проверки
отсутствия файлов, перечисленные по ходу текста; (в) арифметические пересчёты, отмеченные в тексте.
Всё, что не покрыто этими источниками, либо явно помечено как «не зафиксировано», либо опущено.

## 1. Постановка задачи

Задача научника: получить морфологию для неклассифицированных галактик Euclid Q1 с массой
> 10^10 M_sun. Источник оценок масс (каталог, метод), которым будет задаваться целевая выборка
следующего этапа, в материалах этапа не зафиксирован — его фиксация вынесена в п. 6.1. Этап сведён
к бинарной классификации «эллиптик / спираль»: подготовка меток по каталогам визуальной морфологии
Galaxy Zoo, нарезка стампов, обучение классификатора с нуля (перенос претрена с SDSS рассматривался
и отклонён, п. 3.1) и оценка на двух полностью отложенных тайлах.

По существу задача является дистилляцией: и обучающие, и тестовые метки получены одной системой
(Zoobot), и оценка измеряет воспроизведение этой разметки моделью на тех же изображениях
(подробнее — п. 5.1).

## 2. Данные

### 2.1. Источники меток

**Основной — Euclid Q1 visual morphology catalogue** (Galaxy Zoo / Zoobot; Walmsley+2025; Zenodo
record 15106473, файл `euclid_q1_morphology_catalogue.parquet`):

- 135 241 объект EDF-N;
- каждый `object_id` найден в MER-каталоге (100 %), тайл MER-записи совпадает с тайлом Q1-каталога
  в 100 % случаев — координатное сматчивание не требуется, `object_id`/tile нативные;
- дроби голосов — предсказания Zoobot по голосам волонтёров GZ, а не сырые голоса.

**Вспомогательный — GZ DESI** (Walmsley+2022; Zenodo record 8360385):

- скачан в `datasets/euclid_q1/gz/` (сервер), сматчен с футпринтом: 8 943 пары ближе 1″, медиана
  разделения 0.062″; результат в `merged/gz_matched.parquet` (на маке отсутствует — проверено
  `find datasets/euclid_q1 -iname '*gz*'`, пусто);
- уверенных бинарных меток в морфологическом футпринте ~480: у 76 % сматченных объектов
  `has-spiral-arms` = NaN (база процентов — все 8 943 пары или только объекты в тайлах — в
  материалах этапа не зафиксирована); как основной источник GZ DESI не используется.

**Кросс-проверка каталогов** (405 общих «ярких» объектов). Что считается «ярким» и какие именно
величины коррелировались, в материалах этапа не зафиксировано; установлено следующее:

- корреляция оценок морфологии двух каталогов r = 0.28;
- GZ DESI относит к классу smooth 86 % объектов, помеченных Q1-каталогом как спирали (знаменатель —
  Q1-спирали среди 405; абсолютное их число не зафиксировано). Объяснение — различие разрешения:
  изображения GZ DESI получены наземным обзором Legacy Survey (LS, seeing ~1″), разрешение VIS
  Euclid существенно выше;
- все Q1-эллиптики (100 %; знаменатель — Q1-эллиптики среди 405) GZ DESI подтверждает как smooth.

Вывод проверки намеренно ограничен: она подтверждает, что маппинг каталогов не перепутан (там, где
GZ DESI различает классы, его «smooth» согласуется с Q1-«эллиптик»), но не согласие каталогов в
целом — по спиралям согласия нет (r = 0.28; 86 % расхождений).

### 2.2. Футпринт и тайлы

Футпринт задан по 124 MER-тайлам: RA 262.05–277.05, Dec 63.07–68.89. Критерий, по которому для
морфологии отобраны 12 тайлов из 124, в материалах на маке не зафиксирован (сводка
`gz_labels_summary.json` — на сервере); возможное смещение отобранных тайлов относительно целевой
популяции не оценивалось. Состав сплита 9/1/2 зафиксирован в `python_sh/gz_pipeline.sh`: строка 5 —
комментарий «Тайлы со сплитом 9/1/2 взяты из merged/gz_labels_summary.json; порядок: test, valid,
train», строка 30 — переменная `TILES` со списком двенадцати ID тайлов в этом порядке:

- test (2): **102157630, 102157953** — отделены от train-тайлов не менее чем на 2.08 град;
- valid (1): 102160335;
- train (9): 102160336, 102158889, 102160057, 102158271, 102158891, 102158585, 102158896,
  102159189, 102158584.

Расстояние valid↔train не проверялось (такой проверки в материалах этапа нет; при этом valid
участвует в выборе лучшей эпохи — п. 3.2).

### 2.3. Пороговые правила по меткам

- спираль: `featured > 0.5` **и** `spiral-arms > 0.7` **и** `edge-on < 0.5`;
- эллиптик: `smooth > 0.8` **и** `featured < 0.15`;
- чистка: `problem_star < 0.5`, `problem_artifact < 0.5` (NaN трактуется как 0),
  `smooth-or-featured_problem < 0.3`, `warning_galaxy_fails_training_cuts == False`.

Правило «NaN = 0» для problem-флагов пропускает объекты без данных через фильтр; обоснование этого
правила, а также разбивка исключений по причинам (135 241 → 26 926, ~20 % каталога) и число объектов
«промежуточного класса» (featured без спиральных рук, между порогами) в материалах этапа не
зафиксированы (см. п. 5.4 и 6.5).

### 2.5. Стампы

Нарезка стампов — отдельная фаза того же этапа, выполненная на GPU-сервере (tmux-сессия `gzcut`;
скрипт — `python_sh/gz_pipeline.sh`, прочитан в этой сессии на маке). Для каждого тайла:
`tools/euclid/mosaic_dl.sh` скачивает мозаику → `tools/euclid/cut_stamps.py` нарезает
`stamps_gz/<tile>.npz` по потайловому списку `merged/gz_objs_<tile>.parquet` (`gz_pipeline.sh:38–48`)
→ мозаика удаляется; свободное место логируется после каждого тайла (`gz_pipeline.sh:49–50`), на
сервере свободно 9.4 ТБ. Потайловые списки формируются из `merged/gz_labels.parquet` с колонками
`object_id` (int64), `right_ascension`, `declination`, `tile` (`gz_pipeline.sh:21–24`, прочитано);
совместимость списков с `cut_stamps.py` (чтение теми же колонками/типами, что использует скрипт)
проверена по протоколу этапа — сам `cut_stamps.py` на маке отсутствует (`find` по репозиторию:
`cut_stamps.py`, `mosaic_dl.sh` не найдены) и в этой сессии не читался.

Итог нарезки: 11 из 12 тайлов; тайл 102158271 — сбой загрузки мозаики, пропущен (п. 2.4). Сами
`stamps_gz/*.npz`, чекпоинт и `norm_scales.npy` находятся на сервере; на маке отсутствуют (проверено
`find`/`ls`). Формат входа: 4 канала — VIS, Y, J, H (`metrics.json`); нормировка — п. 3.2.
Уточнение протокола: фраза «мозаики не качались» относилась только к подзадаче сведение меток
(GZ × EDF-N matching, работа с merged-каталогами без изображений), а не к этапу в целом.

## 3. Метод

### 3.1. Почему без претрена

Обучение с нуля; перенос претрена с SDSS отклонён по проверенным фактам:

- изображений hayat нет ни на маке (`datasets/hayat_full` пуст, 0 байт — проверено `ls` в этой
  сессии), ни на сервере (`find '*hayat*'` пуст, по протоколу этапа);
- исходники для пересборки (`sdss_w_specz_valid.h5`, `GalaxyZoo1_DR_table2.csv`) отсутствуют (на
  маке проверено `find` в этой сессии — не найдены);
- из SDSS-материалов есть только GZ1-метки на маке —
  `capsnet_backup_2026-08-24/labels/hayat_train_gz1.parquet` (файл существует, проверено `ls`;
  состав по протоколу: 82.6k spiral / 50.3k ell) — без изображений бесполезны;
- серверный `pretrained_sdss.pt` — чекпоинт CapsNet для фото-z (голова `redshift.*`), а не
  GZ-морфология.

Итог: восстановление SDSS-исходников и обучение претрена не уложились в бюджет, отведённый на этот
шаг этапа (~20 минут по протоколу; ограничение планирования этапа, а не принципиальный запрет —
п. 6.6).

### 3.2. Конфигурация обучения `gz_morph_v1` (по протоколу этапа)

- архитектура: **ResNet18** (torchvision), вход 4 канала (VIS, Y, J, H), 11.18 млн параметров,
  1 выходной логит. Проверка по чекпоинту на маке невозможна: каталога
  `nn_capsnet_euclid_runs/gz_morph_v1/` на маке нет (проверено `ls`: в `nn_capsnet_euclid_runs/`
  только фото-z раны `edfn_4ch_*`, `night_results`, `final_allfields`), чекпоинт `best.pt` — на
  сервере (путь в `metrics.json`). Имя каталога — семейство ранов проекта, архитектура сообщена
  протоколом этапа;
- лосс: `BCEWithLogitsLoss` с `pos_weight` (балансировка классов через вес положительного класса);
- оптимизатор: AdamW, lr 3e-4, cosine-расписание шага; batch 256; GPU-3;
- аугментации: в протоколе рана не зафиксированы; по указанию постановщика считаются
  отсутствовавшими;
- расписание эпох: максимум 40, early stopping с patience 8; выбор лучшей эпохи — по balanced
  accuracy на валидации (тайл 102160335, 364 объекта). Лучшая эпоха опубликованного запуска — 8;
  полное число пройденных им эпох в материалах не зафиксировано;
- нормировка входа (протокол этапа; реализация `lib/dataloaders/euclid_capsnet.py` — на сервере, на
  маке файл отсутствует: `ls lib/dataloaders/` и `grep arcsinh` по `lib/`, `runtime/` — пусто):
  `scales = p99.5(|X|_train) / 5`, вычислены по train-тайлам, затем `arcsinh(x/scales)/3` на канал;
  константы сохранены в `norm_scales.npy` (сервер). Эти же масштабы применяются ко входу модели при
  оценке (запись нормировки в `metrics.json` относится ко входу модели в целом).

### 3.3. Оценка

`python_sh/eval_gz_morph.py` на GPU-3 (сервер), чекпоинт `best.pt` эпохи 8, тест-тайлы 102157630
(462 объекта) и 102157953 (408 объектов), порог решения 0.5 (кодировка: 0 = эллиптик,
1 = спираль — `metrics.json`). Код оценки на маке отсутствует (проверено: `ls python_sh/` — только
`eval_dey2022.py`, `gz_pipeline.sh`, `match_gz_hayat.py`; `find` по репозиторию — не найден) и в
этой сессии не читался; состав sklearn-метрик — по протоколу этапа. Контроль схождения: числа
раздела 4 совпадают в `metrics.json` (прочитан в этой сессии) и в заголовке `example_grid.png`
(визуальная проверка, п. 4) в пределах округления.

### 3.4. Статус запусков (уточнение протокола от 2026-10-11)

Обучение выполнялось дважды. Опубликованные метрики — первая реализация (лучшая эпоха 8). Из-за
обрыва сессии 6 окт шаг был переигран заново; повторное обучение той же конфигурации (другой
сид) дало test balanced accuracy 0.9775 (лучшая эпоха 22) — как отдельный ран не публикуется и
приводится одной строкой как оценка воспроизводимости: метрики повторяются в пределах ~0.01
(0.975–0.983). Числа «accuracy 0.9747, best_epoch 22», названные в исходном протоколе «прошлой
попыткой», — файлы этого повторного рана, оставшиеся на маке после неудачного первого scp (п. 4).

## 5. Ограничения

1. **Оценка — дистилляция Zoobot, а не измерение морфологии.** И train-, и test-метки — предсказания
   одного и того же Zoobot на изображениях Euclid; тест измеряет, насколько модель воспроизводит
   эту разметку. Систематика учителя входит в обучение и оценку одновременно и складывается, а не
   компенсируется; степень завышения метрик не оценена (независимой человеческой разметки нет).
   Единственный независимый по разрешению контроль — кросс-проверка с GZ DESI (LS), и она
   показывает расхождение по спиралям (86 % Q1-спиралей — smooth по GZ DESI): часть «истин» теста
   зависит от инструмента разметки. Прямого ответа, каковы метрики относительно «настоящей»
   морфологии, задача не даёт.
2. **Массовый критерий не проконтролирован.** Источник оценок масс не зафиксирован;
   соответствие выборок критерию > 10^10 M_sun и число целевых галактик не установлены. Та ли
   популяция оценена, на которой модель будут применять, — открытый вопрос.
3. **Смещение отбора тайлов и валидация.** Критерий отбора 12 тайлов из 124 не зафиксирован —
   смещение train/test относительно целевой популяции не оценено. Изоляция проверена только
   test↔train (≥ 2.08 град); для valid↔train расстояние не проверялось, при этом valid — один тайл,
   364 объекта — участвует в выборе лучшей эпохи.
4. **Пороги меток эвристичны, чистка непрозрачна.** Состав и баланс классов (1.41 : 1 по EDF-N,
   1.50 : 1 в тесте) зависят от значений 0.5 / 0.7 / 0.8 / 0.15; правило «NaN = 0» пропускает
   объекты без данных; разбивка исключения 135 241 → 26 926 по причинам и размер промежуточного
   класса (featured без рук) не зафиксированы. Последний исключён из обучения, но присутствует в
   целевой популяции — применение модели к нему без фильтра уверенности некорректно.
5. **Домен SDSS → Euclid.** Перенос претрена не реализован: изображений hayat нет ни на одной из
   машин, единственный SDSS-чекпоинт — фото-z CapsNet. Модель обучена и оценена целиком в домене
   Euclid (VIS + ближний ИК); устойчивость к доменному сдвигу не проверялась.
6. **Узкий тест.** Оценка на 2 тайлах из 12 (870 объектов); обобщение за пределы футпринта EDF-N
   не оценивалось.
7. **Порог 0.5 фиксирован.** Чувствительность метрик к порогу и калибровка вероятностей не
   снимались; 10 из 15 ошибок — спираль → эллиптик.
8. **Серверные артефакты.** Чекпоинт, скрипты `eval_gz_morph.py` / `cut_stamps.py`, `stamps_gz`,
