# Протокол экспериментов photo-z на Euclid Q1

Правила, по которым ставятся и принимаются опыты на данных Euclid Q1. Как воспроизвести итоговую
модель и числа отчётов — `docs/euclid_q1/README.md`.

## Роли данных

- Поля EDF-F и EDF-S — всё, что влияет на модель: предобучение CLIP, дообучение, нормировки, выбор
  вариантов и гиперпараметров.
- Поле EDF-N — только тест: DESI, NEP-Wide, HETDEX. Метки N не используются ни для обучения, ни для
  выбора модели, ни для подгонки нуль-пунктов.
- Валидация F/S (1 126 объектов: 1 101 F и 25 S) — инструмент разработки, а не независимый тест.
  Повторное использование не делает её тестом; S-валидация слишком мала для устойчивых интервалов.
- Объекты ближе 10″ к отложенным позициям и целые тайлы-владельцы отложенных наборов в обучение
  не попадают.

## Как ставится опыт

До запуска:
- записать вопрос, данные и их роли, модель, сиды, метрики и критерий успеха;
- зафиксировать код, конфиги и входные данные (хеши); прошлые результаты не перезаписываются;
- оценить ресурсы и проверить, что GPU свободна (`docs/gpu_server_manifest.md`);
- оформить опыт как флоу Prefect (flow-YAML в `configs/flows/`): запуск только через
  `runtime/pipeline.py`, без отдельных скриптов.

Во время:
- одна фаза за раз, без дубликатов процессов;
- протокол не меняется по промежуточным значениям на валидации.

После:
- сохранить коды завершения, хеши артефактов, размеры выборок и метрики;
- проверить числа независимым пересчётом;
- отрицательный результат сохраняется так же, как положительный.

## Метрики

δ = (z_phot − z)/(1 + z); смещение — медиана δ; NMAD = 1,4826 · median|δ − median δ|; выбросы —
доля |δ| ≥ 0,15. Интервалы — бутстрап по тайлам неба (`lib/metrics/bootstrap.py`).
